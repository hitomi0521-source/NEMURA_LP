# NEMURA「Night Reset」ランディングページ

機能性表示食品（GABA 100mg 配合）のLP制作課題です。すべて架空の商品・企業・監修者で、
届出番号「X999」もダミーです。

## 公開ページ

| ファイル | 内容 |
|---|---|
| `index.html` | LP本体。SP（375px）を基準に、600px・1024px でレイアウトが切り替わります |
| `confirm.html` | 最終確認画面。特定商取引法で必要な7項目を掲載し、支払方法に応じて合計金額が再計算されます |
| `thanks.html` | 申込完了画面 |

| `terms.html` | 利用規約（全13条） |
| `privacy.html` | 個人情報の取扱い。Cookieの利用は `#cookie` に |
| `contact.html` | お問い合わせ窓口 |
| `fv3.html` | ファーストビュー3案の比較（悩み共感軸／価格軸／成分・信頼軸） |

申込フォームから `confirm.html` → `thanks.html` まで実際に遷移します。
確認画面の「修正する」は申込フォームへ戻ります。

## 申込みデータの扱い

`index.html` のフォームを送信すると、入力値を `sessionStorage`（キー `nemura_order`）に保存して
`confirm.html` へ遷移します。確認画面は保存された値を読み出して表示し、「この内容で申し込む」を
押すと `thanks.html` へ進みます。完了画面は注文番号（`nemura_orderNo`）を表示したあと、
二重計上を避けるため両方のキーを削除します。

保存先はタブを閉じると消える `sessionStorage` です。`localStorage` は端末に残るため、
氏名・住所・電話番号を扱うこの用途では使っていません。

### 公開状態では外部に送信しません

これは架空の商品を扱う制作課題で、誰でも開ける場所に置いてあります。そこから氏名・住所・
電話番号を実際に外部へ送れる状態にしておくと、事情を知らない訪問者が本物の情報を入力して
送ってしまう余地が残ります。受け取る側にも預かる理由がないので、**送信先を空にしています。**

```js
var ENDPOINT = '';
```

空のときは送信をとばして完了画面へ進むので、`index` → `confirm` → `thanks` の画面遷移と
入力内容の引き継ぎは、公開状態のままひととおり確認できます。

さらに安全弁として、URLを入れ忘れて公開した場合でも送信されないようにしてあります。

```js
function canSend(){
  if (!ENDPOINT) return false;
  var h = location.hostname;
  return h === 'localhost' || h === '127.0.0.1' || h === '' || h === '[::1]';
}
```

スプレッドシートへの記録まで動かして試したいときは、**ファイルを書き換えずに**、手元のブラウザの
コンソールで次を1回実行します（`localhost` で開いている必要があります）。

```js
localStorage.setItem('nemura_endpoint', 'https://script.google.com/macros/s/.../exec')
```

その端末でだけ送信が有効になります。戻すときは `localStorage.removeItem('nemura_endpoint')`。
ファイルにURLを書くと、戻し忘れたまま公開してリポジトリの履歴に残るため、この形にしています。

受け口側の実装（`doPost`／注文番号の採番／自動返信メール）は、別紙
「NEMURA_申込管理_やり方.md」にまとめています。

申込フォームの冒頭には、架空サイトであることと「実在の個人情報は入力しないでください」を
本文と同じ大きさで置いています。フッターの注記だけでは、フォームまで来た人の目に入りません。

### 郵便番号からの住所自動入力

「住所を自動入力」を押したときだけ、外部の住所検索API（zipcloud）に問い合わせます。
以前はどの番号を入れても同じサンプル住所を返す仮実装で、実質動いていませんでした。

このAPIは CORS を明記していないため、まず `fetch` を試し、弾かれたら JSONP（script タグ）に
切り替えます。どちらも失敗したときは「住所を取得できませんでした。お手数ですが直接ご入力ください」
と案内し、手入力で先に進めます。**どの経路でもフォームは止まりません。**

### 申込完了画面の表示

送信を止めているのに「確認メールをお送りしました」と書いてあると、届かないメールを待たせて
しまいます。完了画面の冒頭に、架空サイトであり申込みもメール送信も発生しないことを明記しました。

### その他

フォームには、人には見えない入力欄（ハニーポット）を1つ置いています。
自動投稿プログラムはここを埋めてしまうため、値が入っていた送信は受け口側で捨てられます。

**クレジットカード番号・有効期限・セキュリティコードはこのフォームでは一切扱いません。**
本番では決済代行会社の画面へ渡す設計になります。

```

```

`style.css` と `script.js` はページごとに名前空間を切っています。各ページの `<html>` に
`p-index` `p-confirm` のようなクラスが付いていて、CSSはそのクラス配下に、JSは該当クラスの
ときだけ実行されるように書かれています。ページを追加するときは、同じ約束に従ってください。
規約系の4ページは体裁が同じなので、`p-doc` を共有して1ブロックにまとめています。

## 公開URLが決まったら足すもの

`index.html` の `<head>` に2行。いまは実在しないURLを書くほうが害が大きいので入れていません
（架空ドメインを正規URLとして宣言すると、GitHub Pages 側が検索結果から外れます）。

```html
<link rel="canonical" href="https://ユーザー名.github.io/リポジトリ名/">
<meta property="og:url" content="https://ユーザー名.github.io/リポジトリ名/">
```

`og:image` / `twitter:image` は相対パスにしてあるので、そのままで各SNSが解決します。

## 実装メモ

- SPファースト。`600px` でカラム幅を固定し、`1024px` でマルチカラムへ
- FVの写真は2枚を6秒ごとに切り替えます（①商品のパウチ ②就寝前の2粒と水）。
  **どちらも商品そのものです。** 初回特典のハーブティーも候補にしましたが外しました。
  ハーブティーは機能性表示食品ではなく、機能を表示できません。「眠りは、整えられる。」という
  見出しの真下に商品と同じ大きさで置くと、そのお茶にも同じはたらきがあるように読めてしまいます。
  特典は⑨で「初回特典」と分かる文脈のなかで見せています。**コピーは動きません。**
  文字まで入れ替えると、読んでいる途中で消える・レイアウトががたつく・毎回コントラストを
  測り直す必要が出るためです。1枚目だけHTMLに直接置いてLCPとして先に読み込ませ、
  2枚目は読み込み完了後に `<template>` から複製して足します（JSが動かなければ1枚のまま）。
  一時停止ボタンを置き、マウスが乗っている間とタブが裏に回っている間も止めます。
  動きを減らす設定の端末では、自動送りそのものを行いません（WCAG 2.2.2）
- FVは写真を画面いっぱい（`100svh`）に敷き、その上にコピーを置いています。PCはパウチが右に
  写るので文字はすべて左半分に、スマホは写真の上半分が暗く空いているのでそこに載せています。
  写真の上の文字は、写真だけを描画した画面から画素を採って、最も条件の悪い1%を除いた値で
  コントラストを実測しています（2枚それぞれで測り、いちばん条件の悪いところで 6.48）
- 画面の縦が短いノートPCでは、文字と余白を一段階詰めてCTAまでを1画面に収めています
- 写真は WebP と JPEG の2系統を用意。`<img>` は `<picture>`、CSSの背景画像は `image-set()` で
  出し分けています。FVビジュアルのみ `preload` + `fetchpriority="high"`
- `images/` に置いてあるファイルは全点どこかから参照しています（未使用の画像はありません）
- ④の商品写真は、スマホでは横スワイプ（CSSの `scroll-snap`）、600px以上では横並びに切り替わります。
  現在位置の点は「実際に画面からはみ出しているとき」だけJSで出しています。並んで全部見えているのに
  点があると、押しても何も起きないため。スクロールできる状態のときは `tabindex` を付けて、
  キーボードでも動かせるようにしています
- 主要CTAには `data-cta`、各セクションには `data-section` を付与し、GTM/GA4 から参照できるようにしています
- 写真の上に載るテキストは、すべて WCAG AA（4.5:1）を満たすことを実測で確認しています
- 320〜1600px の9段階で、全ページに横スクロールが出ないことを実測で確認しています
- ページを開いたときの外部リクエストはゼロです（唯一の例外は、郵便番号の「住所を自動入力」を
  押したときだけ呼ぶ住所検索API）。SNSアイコンはインラインSVG、Webフォントも読み込んでいません。
  端末に入っているフォントだけで組み、Windows／macOS のどちらでも自然な字体が出るよう
  候補を並べています（明朝は Noto Serif JP → ヒラギノ明朝 → 游明朝 → MS P明朝）。
  Google Fonts を読めば全端末で同じ字体になりますが、日本語フォントは重く、
  現在53万バイトのページに100〜300KB増えるため、この課題では見送っています
- ボタンの hover は `@media (hover:hover) and (pointer:fine)` の中だけに書いています。
  タッチ端末に効かせると、指を離したあとも明るいまま残るためです
- FVのpreloadは `media` でPC用とスマホ用を出し分けています。付けないと、PCでも
  スマホ用の縦長画像を先に取りに行ってしまいます
- **HTMLに `style=""` は1つもありません**（全9ページ実測）。同じ意味の余白が
  18px / 20px のようにずれていくのを防ぐため、`.gap-s` `.gap-m` `.gap-l` の3段階に
  丸めて `style.css` に集約しています
- favicon は頭文字の「N」だけの角丸マーク。字の太さと縦横比はロゴ「NEMURA」のNに合わせ、
  16pxで消えない範囲でだけ太らせています。要素はこれ以上足していません。
  文字はフォントではなくパスで描いてあり、`favicon.svg` / `favicon.ico` / `favicon-180.png`
  （iOSホーム画面用）の3種を用意しています。`favicon.ico` はブラウザが `/favicon.ico` を
  勝手に取りに来るぶん、サイト直下にも置いています
- 商品パッケージの文字は、写真の上に後から合成しています。斜めのカットでは面の傾き・
  奥行きによる圧縮・膨らみを計算して歪ませ、印刷されているように見せています

## 制作物としての制限

- 遷移先のないリンクが3種あります。いずれも架空ブランドゆえに実体が作れないものです
  - フッターのSNSアイコン4種 … `href` を持たせず、押しても何も起きない状態にしています
  - LINEの友だち追加ボタン … 架空ブランドなのでアカウントが存在しません。押しても何も
    起きないリンクにするとUXとして成立しないので、**押せない見本**として置き、
    「本課題では動作しません」と理由を添えています。本番では友だち追加URLに差し替えます
  - `fv3.html` のCTA … ファーストビュー案の見本内のボタンなので、遷移先はありません
- マイページ（周期変更・スキップ・解約）は静的サイトのため未実装です。
  完了画面からは `contact.html` に導いています
- SNSアイコンは公式グリフを再現したSVGです。公開前に各社ブランドサイトの公式アセットへ
  差し替えてください。LINEの「友だち追加」導線は、LINE公式の友だち追加ボタン素材を使うのが原則です
